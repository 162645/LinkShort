## 2. 深度架构设计与数据流向

### 2.1 请求重定向全链路
当用户访问一个短链接时，`redirect-svc` 遵循以下路径：
1.  **L1 Local Cache (进程内)**: 微秒级检索。
2.  **Bloom Filter (Redis Bitset)**: 瞬间识别 100% 的不存在短码，防御缓存穿透恶意攻击。
3.  **Singleflight 控制**: 针对同一热点短码，确保只有一个协程去穿透后端，防御缓存击穿。
4.  **L2 Redis Cache (分布式)**: 毫秒级检索，确保分布式节点间的数据一致性。
5.  **PostgreSQL (持久化)**: 最终兜底。
6.  **异步埋点**: 统计信息通过 **NATS 消息队列** 异步发送至 `analytics-svc`，确保主路径延迟不受日志采集影响。

### 2.2 短码生成与位数扩展逻辑 (Mathematics)
系统采用 **Redis 分布式计数器 + Base62 编码**。
- **初始偏移量**: 系统计数器从 `10,000,000,000` (100 亿) 开始起跳。
- **6位扩展至7位**: 
  - 在 Base62 编码中，$62^6 = 56,800,235,584$ (约 568 亿)。
  - 当计数器处于 `[100亿, 568亿]` 区间时，Base62 映射结果固定为 **6位字符串**。
  - 当计数器超过 `56,800,235,583` 后，Base62 映射结果将自动平滑扩展为 **7位字符串**。
- **设计优势**: 既保证了初期用户体验的紧凑感（6位），又具备了承载 **3.5 万亿** ($62^7$) 数据量的扩展能力，无需任何架构变更。

## 3. 简历描述锦集 (专业视角)

**岗位/项目经验：核心开发 / 架构优化**

- **多级缓存架构**: 实现 **L1 (go-cache) + L2 (Redis)** 双层缓存机制，针对极热点请求实现 **98%+** 的内存级拦截，TTFB 降至 **3.8ms**。
- **并发防护体系**: 设计并落地 **布隆过滤器 (Redis Bitset)** 与 **Singleflight** 合并请求技术，成功拦截 100% 缓存穿透攻击，解决雷鸣死锁（Thundering Herd）问题。
- **高性能 ID 生成**: 弃用 Snowflake 转向 **Redis 原子计数器 + Base62** 方案，解决了分布式时钟回拨隐患，并支持容量从 6 位到 7 位的无损弹性扩展（支持 3.5 万亿短码）。
- **分布式观测能力**: 深度集成 **Prometheus + Grafana + NATS**。通过自定义 Exporter 实现了数据库连接池细粒度监控，并将 P99 延迟控制在 **10ms** 以内。
- **异步解耦设计**: 利用 **NATS 消息队列** 实现重定向逻辑与埋点分析的解耦，大幅提升重定向吞吐能力，并确保分析数据零丢失。
